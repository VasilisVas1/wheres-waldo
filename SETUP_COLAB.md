# Running this project on Google Colab

All heavy computation should run on Colab, not locally — in practice that means notebook 04 (YOLO
training) on Colab's free GPU; everything else is light enough for a CPU runtime. This is a one-time setup; after that, every notebook auto-detects Colab and handles
mounting/installing/paths itself.

> **Important — if you already ran notebooks 01/02 before this file was updated:** the notebooks
> originally worked directly out of Google Drive, and that turned out to be badly wrong — Drive is a
> network filesystem, and reading thousands of small training-patch files from it individually (which a
> training loop does every epoch) made training take *hours* instead of minutes. The fix (below) copies
> everything to Colab's local disk once per session instead. Because of that, **restart your Colab
> runtime and re-run from notebook 01** — any files already generated under the old scheme have Drive
> paths baked into them and won't work with the fixed notebooks. Re-running 01/02 is fast (no training),
> so this doesn't cost much.

## 1. Upload the project to Google Drive

In Google Drive, create a folder at **`My Drive/wheres-wally`** (the exact name matters — every
notebook looks for the project at `/content/drive/MyDrive/wheres-wally`). Upload into it:

- `src/` (all the shared code)
- `notebooks/` (all 5 `.ipynb` files)
- `requirements.txt`
- `Hey-Waldo/` — **your existing local folder**, the one you already downloaded from Kaggle. Drag the
  whole folder into Drive (or use Google Drive for Desktop / `rclone` if you have it, since it's ~7,000
  small files and the web uploader can be slow with that many individual files — zipping it first and
  unzipping inside Drive, or uploading the zip and extracting via a Colab cell, is usually faster than
  dragging 7,000 files through the browser). This one-time upload is the only place you'll feel Drive's
  many-small-files slowness — after that, notebooks only read Hey-Waldo once (to copy it locally), never
  repeatedly.

Do **not** upload `.venv/`, `data/`, `models/`, `runs/`, or `.git/` — everything in `data/` and
`models/` is regenerated by the notebooks themselves.

## 2. Add your Roboflow API key

Create a plain text file named `.env` inside `My Drive/wheres-wally/` (same folder as `src/`) with one
line:

```
ROBOFLOW_API_KEY=<your key>
```

(The same key already sitting in your local `.env` file works — just copy that one line.)

## 3. Open the notebooks in Colab

From Google Drive, right-click each notebook → **Open with → Google Colaboratory** (or go to
[colab.research.google.com](https://colab.research.google.com) → File → Open notebook → Google Drive,
and pick it from `wheres-wally/notebooks/`).

**Pick the runtime deliberately — the free GPU quota is limited and it runs out.** Only notebook 04
(YOLO) meaningfully benefits from a GPU. Run notebooks 01, 02, 03 and 05 on a plain **CPU** runtime
(Runtime → Change runtime type → CPU), which doesn't consume GPU quota, and switch to **T4 GPU** only
for notebook 04. The setting doesn't carry over between notebooks opened separately.

## 4. Run the notebooks in order

1. `01_data_exploration.ipynb` — downloads the Roboflow dataset (needs the `.env` key from step 2),
   cleans it down to 19 verified scenes.
2. `02_preprocessing.ipynb` — k-fold split, patch generation, Hey-Waldo patch corpus, synthetic
   copy-paste crop pool.
3. `03_train_sliding_window.ipynb` — trains the from-scratch classifier. A tiny CNN: fine on CPU
   (slower than GPU, but free of GPU quota). Optional if you already have a trained
   `sliding_window_classifier.pt` — see the note below.
4. `04_train_yolo.ipynb` — fine-tunes YOLO with synthetic augmentation across all 5 folds. This is the
   heaviest step; GPU plus local-disk data should take it from hours down to well under an hour.
5. `05_evaluation_error_analysis.ipynb` — final comparison and write-up.

**How the first cell works now:** it mounts your Drive, then — if it hasn't already this session —
copies the whole project (code, `Hey-Waldo/`, any data already generated by an earlier notebook) from
Drive to Colab's local disk at `/content/wheres-wally`, and does all its actual work there. That copy
takes a few minutes the first time in a fresh runtime (it's still reading Hey-Waldo's many files once)
but is not repeated for every subsequent cell — expect one multi-minute pause at the very start of each
notebook, not the hours-long hang from before. It also installs the few packages Colab doesn't already
have (`roboflow`, `ultralytics`, `albumentations`, `lxml`, `pyyaml` — Colab already ships `torch` with
CUDA support, so that's not reinstalled).

**How results get back to Drive:** the *last* cell of notebooks 01-04 calls `sync_to_drive(...)`, which
copies that notebook's outputs (manifests, patches, trained models) from the local copy back to your
Drive folder in one bulk operation. This is what lets the *next* notebook — possibly a fresh runtime —
pick up where the previous one left off. **Don't skip running the last cell of each notebook**, or its
outputs won't be there for the next one.

If a runtime disconnects partway through and you reconnect (or open the next notebook in a fresh
runtime), that's fine — as long as the previous notebook's last (`sync_to_drive`) cell finished, the new
runtime's first cell will find everything it needs on Drive and re-copy it locally.

## 5. Getting results back to your local machine

Once notebooks 03-05 finish, download these from your Drive folder back into your local project at the
same relative paths:

- `models/sliding_window_classifier.pt`
- `models/yolo_detector.pt`
- The executed `notebooks/*.ipynb` files (so the local repo has the real, current outputs)

Then the local Streamlit app (`streamlit run app/main.py`) will use the freshly-trained models.
